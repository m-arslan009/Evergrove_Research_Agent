Understanding B-tree indexes

An index is a structure that stores keys in sorted order together with a pointer back to the row they belong to. A lookup becomes a walk down a tree instead of a scan of the whole table, and the advantage grows with the size of the table.

Why the tree stays shallow

A B-tree is balanced, so every leaf sits at the same depth and a lookup costs a predictable number of steps. Entries are also held in order, which is what lets one index satisfy a sort as well as a filter.

An index nothing queries is pure overhead: it still has to be maintained on every insert, update and delete.

Checking what the planner did

Run the statement through EXPLAIN ANALYZE and compare the estimated row counts with the actual ones.

EXPLAIN ANALYZE
SELECT id, title
FROM articles
WHERE author_id = 42;

A large gap between the estimate and the result usually means the statistics are stale rather than that the index is wrong.
